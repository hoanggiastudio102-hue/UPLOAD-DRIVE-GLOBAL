API:
GET /health -> {ok:true, service:'DriveDrop', version:'0.3.0', google_connected:bool, album_routing:true}. Updated Employee requires album_routing to be exactly true before claiming or processing media, including pending jobs; an older Boss leaves local files untouched and asks for a Boss update.
POST /enroll unauth {code, name} -> {device_id, secret, daily_limit_bytes}; codes single use expire 15 min.
POST /uploads authenticated {request_id:UUID, name, size:int, sha256:hex64, md5:hex32, source_folders?:list[str]} -> {upload_id, file_id, session_url, state:'pending'|'verified', size, sha256, destination?:str}. source_folders is outer-to-inner folder basenames, starting with the selected watch root basename and ending with the original file's parent. Each element must be printable, nonempty, not '.'/'..', contain no slash/backslash, be at most 200 characters; at most 32 elements and 6000 UTF-8 bytes total. Missing context remains supported for legacy clients; null is invalid. Context presence and exact list are durably bound to request_id: changing, adding, or dropping context on replay is 409 even if name/size/hashes match. Request id scoped per device is idempotent. Only image/video suffixes; MIME server derived. Quota reserves bytes before creating session. Sessions encrypted at rest; Google OAuth never sent client.
POST /verify authenticated {upload_id} -> {verified:true, upload_id,file_id,size,sha256,md5} only after independently fetching expected stored Drive fileId, expected parent, size, md5/sha256. 409 means not ready/mismatch, not verified. Don't trust client fileId. Session retry same upload; expired requires explicit /uploads/restart {upload_id} creates new session reusing pre-generated Drive fileId ONLY if confirmed missing; otherwise verifies expected file. Returns same shape.

Enrollment config exported by boss: {server_url:'https://IP:48765', certificate_sha256:'hex', code:'single-use'}.
Client config: {server_url,certificate_sha256,device_id,watch_folder,delete_after_verify:false,poll_seconds:30,stable_seconds:30}; secret stored via SecretStore(directory,'DriveDropClient'). Client data sqlite journal persists request_id/upload_id and original source_folders with claim intent across restart. Legacy jobs with no context row omit the field. Recursively scan the selected watch root; never follow symlinks or junctions; ignore hidden folders and incomplete extensions. Claim ready file via atomic rename into .drivedrop-pending same root before hash/upload; persist original relative path and restore a preserved file into the same nested folder. Persist claim recovery, detect changes before/after upload and before deletion; producer contract files must be closed and atomically renamed into watch folder. Successful default preserves source, optional verified deletion. Don't auto-delete uncertain/changed bytes. Avoid name collisions and duplicate upload on lost responses. Client never forwards Google session URL to anything other than Google, never logs it.

Routing: ChannelCatalog.route_context(filename,kind,source_folders) gives article/subfolders for media inside the nearest exact known CODE_digits folder. Canonical article uppercases the code and preserves the digit string. Images use that folder before the filename, producing channel/ANH/article/subfolders/file. A disabled nearest matching article falls back to KÊNH. Without an article folder, images keep filename routing. Videos use the nearest article folder first, just like images; without one, an explicit filename code is used. A leading VIDEO container under a video article or ANH/ẢNH under an image article is stripped; other descendant folders are retained. Videos now produce channel/VIDEO/article/subfolders/file. Unknown contexts fall back to KÊNH/file. Broker records context in upload_context and destination in upload_routes atomically with the upload; an existing upload's parent remains pinned across mapping edits and restarts. GoogleDrive.resolve_article_folder(channel_id,name,code,article,subfolders=(),kind='ANH') returns the leaf parent; VIDEO folder identities include the media kind while preserving existing ANH identities.

Admin-only Broker.regroup_verified_videos(article,log,require_source_match=True) moves verified flat VIDEO uploads of the selected channel, checking Google size/SHA256/MD5 and parents before and after, and updating upload and route parents. The default requires recorded source context to match the article. The Boss GUI explicitly assigns the whole channel's verified flat batch to the article (require_source_match=False); the operator must establish that all candidate files belong to it. Pending uploads, other channels and untracked files are excluded. Retries recover a completed remote move before the database commit without duplicating content. GoogleDrive.move_file_parent(file_id,old_parent,new_parent) changes only parents.

Background mode (0.3.0): new client configurations default to poll_seconds=30; existing saved values remain until reconfiguration. POST /heartbeat is device-authenticated and accepts bounded state/progress fields only. Server timestamps drive the 60-second stale indicator. Heartbeats do not authorize uploads or deletion. GET /health additionally returns worker_status:true. The desktop monitor refreshes every 5 seconds; client reports every 15 seconds. Article totals come from issued/verified broker records, not a claim that every local file was discovered.

The Mac LaunchAgent runs only in the enrolled user's login session, retaining the existing Employee state/Keychain and exclusive worker lock. Windows supervise restarts a crashed child but respects intentional exit; a login Startup shortcut is separate from the app package. Closing the Boss window hides it when the tray is available.

Distribution archives contain no real credentials or runtime state.
